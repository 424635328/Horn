# 平台适配

同一份内容在不同平台上的渲染差异，集中在四处：**公式分隔符、折叠块、图表语法、行内样式**。其余结构规则通用。

## 1. 平台对照

| 能力 | 通用 Markdown（GitHub / GitLab） | 语雀 |
|---|---|---|
| 行内公式 | `$...$`（GitHub 支持） | `$...$`，**不认** `\(...\)` |
| 块级公式 | `$$...$$` | `$$...$$`，且 `$$` 独占一行 |
| 折叠 | `<details><summary>` | 原生折叠（输入 `/折叠` 或 `>>>`），**不认** `<details>` |
| 流程图 | Mermaid 代码块 | Mermaid，但内核较旧、容错低 |
| 行内着色 | 不支持 HTML 颜色 | 支持 `<font color="#1890FF">` 等 |
| 分割线 | `---`，前后留空行 | 同左，且粘连时会拖垮公式解析 |

**未验证的平台**（飞书、Notion、Confluence 等）：按通用 Markdown 产出，交付前在目标平台抽查三处——表格是否错位、代码块语言是否识别、公式是否渲染。不要凭印象断言"应该没问题"。

## 2. 通用 Markdown

- 标题层级不跳级；一篇只保留一个一级标题。
- 表格必须有表头与分隔行，列数一致；单元格内竖线写成 `\|`。
- 代码块标注语言；嵌套代码块外层用四个反引号。
- 相对链接在 README 里可用；跨仓库引用用完整 URL。
- `<details>` 可用于长附录，但不要把正文关键结论藏在里面。

## 3. 语雀

### 3.1 公式

- 行内 `$...$`，块级 `$$...$$`，块级符号独占一行。
- 不用 `\(...\)`、`\[...\]`——不会被转换，会原样显示反斜杠。
- 公式里出现竖线用 `\vert` / `\Vert`，否则在表格中会截断列。
- 正文里的美元符号写成「美元」，避免触发公式解析。

### 3.2 折叠与分割线

- 折叠用原生折叠块，不用 `<details>`：块内 Markdown 与换行都不解析，内容会挤成一行。
- `---` 前后各留一个空行，否则与上下文粘连，严重时连带公式转换失效。

### 3.3 Mermaid

| 不要写 | 正确写法 | 后果 |
|---|---|---|
| `subgraph 中文` / `subgraph 中文：` | `subgraph SG1["中文标题"]` | 缺英文 ID 且跟全角冒号，词法解析中断 |
| `A <-->\|"文字"\| B` | `A ---\|"文字"\| B`，或拆两条单向箭头 | 双向箭头带标签会让整块图报错 |
| `A[文本(说明)]` | `A["文本(说明)"]` | 括号、引号、井号会截断节点文本 |
| `end` 作节点 ID | `END_NODE["结束"]` | `end` 是子图结束关键字 |

图类型优先用 `flowchart`、`sequenceDiagram`、`stateDiagram-v2`、`erDiagram`、`gantt`、`pie`；`mindmap`、`timeline` 等新类型在部分语雀版本不渲染，改用 flowchart 表达更稳。

Mermaid 报错时按此顺序排查：首行类型声明 → 子图声明 → 双向箭头标签 → 节点文本特殊字符 → 是否混入 PlantUML/Graphviz 语法。

### 3.4 表格与代码

- 单元格里不能放列表、代码块、块级公式；行内公式与行内代码可以。
- 单元格内的竖线必须转义，否则整张表错位。
- 代码块标注语言；破坏性命令在注释里写明影响范围。

## 4. 其他交付形态

| 目标 | 做法 |
|---|---|
| Word / PDF | 交给 `docx` skill；内容仍按本 skill 的写作规范产出 |
| 演示文稿 | 交给 `ppt` / `pptx` skill；一页一个结论，不整段搬运 |
| 仓库内 README | 按通用 Markdown；开头三行说清"这是什么、给谁用、怎么开始" |
