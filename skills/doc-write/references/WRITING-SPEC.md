# 写作规范

本文件回答四件事：写多深、按什么顺序写、怎么让例子站得住、怎么自查。排版只管"看起来对不对"，这里管"读了有没有用"。

## 1. 读者契约

动笔前固定一个具体读者，而不是"一般读者"。默认画像是：**有该领域入门基础，但没形成体系，需要照着做或做判断**。

为整篇写一句契约：**读者是谁、读完能做什么、本文件不解决什么**。三个空都要填实：

- "能做什么"必须是动作："能独立完成一次灰度发布"，不是"了解灰度发布"。
- "不解决什么"决定边界，也决定读者会不会误用。
- 契约里出现"全面""深入"这类词，说明还没想清楚。

## 2. 五层解释法

每个核心概念按需覆盖以下五层，顺序即写作顺序。

| 层 | 要回答的问题 | 常见失败 |
|---|---|---|
| 定义 | 它究竟指什么，边界在哪 | 抄教科书原句，术语套术语 |
| 问题 | 它为解决什么痛点而出现 | 直接给结论，读者不知道为何需要 |
| 直觉 | 能否用一个画面或类比建立心智模型 | 类比贴切但没说明哪里不贴切 |
| 机制 | 内部组成、状态变化、调用关系、执行流程 | 只描述现象，不描述因果 |
| 边界 | 什么情况下不适用，与相近概念差在哪 | 只讲优点，不谈代价与失效条件 |

**类比规则**：类比只负责建立直觉，不负责证明结论；类比之后必须回到准确定义；类比有局限时当场说明"这个类比在 ______ 处失效，因为 ______"；一个概念只用一个主类比。

## 3. 金字塔与章节

1. **结论先行**：每节开头 1~3 句给结论或总览，只读每节开头也能拿到骨架。
2. **以上统下**：下级标题必须能被上级概括；放别处也成立的小节，说明分类依据不一致。
3. **分类清晰**：同层只用一种划分标准，不要混用"按模块""按时间""按难度"。
4. **逻辑递进**：后一节用到前一节的概念；并列堆砌等于没有主线。

粒度经验：每节只承担一个认知任务；连续三个只有一两句话的段落，说明该合并或该补解释；一级章节原则上不超过 9 个。

## 4. 示例与操作型内容

示例的唯一标准是**能体现核心机制**：

- **最小**：删掉与机制无关的代码、配置与铺垫。
- **自洽**：代码、输入、输出、正文结论四者一致；改了代码要同步改结论。
- **不重复**：三个本质相同的例子，不如一个例子加一个变式。

操作型内容必须补齐五件事：

| 要素 | 具体内容 |
|---|---|
| 前置条件 | 系统、运行时版本、权限、依赖、环境变量 |
| 操作步骤 | 可直接执行的命令，按顺序编号，标明执行环境 |
| 参数说明 | 只解释非显而易见的参数、默认值与作用 |
| 验证方法 | 怎么确认成功：预期输出、退出码、文件是否生成 |
| 失败恢复 | 常见报错、原因、回滚或重试方式 |

涉及破坏性操作（删除、覆盖、格式化、批量迁移）时，写明影响范围、执行前检查项与恢复手段。

## 5. 事实、来源与不确定性

按可信度分四级，写作时明确自己在用哪一级：

| 级别 | 例子 | 写法要求 |
|---|---|---|
| 客观事实 | 规范、数学定义、语言标准 | 可直接陈述，必要时给来源 |
| 普遍实践 | 主流框架的默认配置 | 说明"主流""默认"的范围与版本 |
| 经验建议 | 调优的常见做法 | 说明适用条件，承认存在其他做法 |
| 个人判断 | 选型偏好 | 标注为判断，不伪装成事实 |

易变信息（版本行为、产品参数、法规、价格）必须带版本号或日期。无法实时核验时写清核验边界，例如"以下基于 x.y 版本文档，更新版本可能变化"。

参考资料只列真正用到的来源且可核实。宁可不列，也不要编造标题、作者、URL 或 DOI。

## 6. 自检清单

逐项过，任一项不过就改。

1. **结构**：主线是否清晰？每节是否有中心结论？上下级标题是否真有概括关系？
2. **覆盖**：定义、机制、区别、应用、边界是否齐全？有没有明显遗漏？
3. **逻辑**：有无概念混淆、重复论述、论据不支撑结论、分类依据不一致？
4. **准确**：公式、推导、代码、版本信息是否一致？哪些结论需要补限定条件？
5. **实用**：读者能否据此操作、判断或排错？前置条件与验证方法是否齐全？
6. **排版**：表格列数、代码块语言、链接、公式是否符合目标平台？
7. **可维护**：三个月后改这一节，能否一眼看出哪些数字、版本、结论需要同步？
8. **冗余**：是否存在删掉也不损失理解的空话、重复解释与装饰性内容？

## 7. 反模式

| 反模式 | 症状 | 改法 |
|---|---|---|
| 定义堆砌 | 开篇三段全是定义 | 先给问题场景，再给定义 |
| 术语掩护 | 用未解释的术语解释另一个术语 | 每个新术语先给一句大白话 |
| 伪精确 | "性能提升 300%"没有测量条件 | 补测量方法、环境与基线，或改定性 |
| 绝对化 | "必须""唯一""永远不要" | 改条件句，说明例外 |
| 正确的废话 | "要注意安全性""要合理配置" | 换成可执行的检查项 |
| 目录复述 | 总结部分重复各级标题 | 改为结论与因果链 |
| 例子同质 | 三个例子讲同一件事 | 留一个，补一个变式或反例 |
| 装饰性图表 | 只有两个节点的流程图 | 改为一句话或列表 |
| 过度强调 | 每段都有加粗和颜色 | 每段最多一处强调 |
